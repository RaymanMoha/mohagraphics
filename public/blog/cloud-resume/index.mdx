## My portfolio lives in the cloud 🌩

This is what happens when you click on [mohammed.tech](http://mohammed.tech/)

[Route 53](https://aws.amazon.com/route53/) routes your request to the HTML, CSS and JS files which live inside a [S3](https://aws.amazon.com/s3/) storage bucket. These are cached by [Cloudfront](https://aws.amazon.com/cloudfront/). That means there's **a copy of them across 200+ locations around **the world. So no matter if you connect from Singapore or France, you'll get the content as fast as possible.

Remember, **the internet is a bunch of physically connected computers** exchanging information at (close to) the speed of light. Being closer to the information you want, means faster loading times.

Click [here](https://www.cloudping.info/) if you want to know what's the nearest AWS location to you.

## The Architecture Deep Dive 🏗️

**Frontend Layer**: Static HTML, CSS, and JavaScript files hosted in S3 with static website hosting enabled. This eliminates the need for traditional web servers and provides infinite scalability.

**CDN Layer**: CloudFront distribution ensures global content delivery with edge caching, SSL termination, and DDoS protection out of the box.

**API Layer**: Lambda function handles dynamic functionality (visitor counter) without maintaining server infrastructure. It only runs when triggered, making it incredibly cost-efficient.

**Database Layer**: RDS MySQL instance stores visitor analytics and any dynamic data. For higher performance and lower cost, consider DynamoDB for simple key-value operations.

**Meanwhile on the client side**

When you connect to the [site](http://mohammed.tech/) you trigger a [serverless function](https://aws.amazon.com/lambda/). This means that instead of having a server running 24/7 waiting for a request, **the function only exists on demand**.

This function (written in Python because why not) queries my RDS database. It gets the visitor count, adds one and updates the table. The function returns the new value and displays it on the site.

## DevOps and Automation 🚀

**Continuous Deployment**

On Github, when I push changes to the main branch. They trigger an action that **replaces the files in the S3 bucket and invalidates the cached files on Cloudfront**. This means that the next time you connect, you'll get the latest version of the files.

**Infrastructure as Code**: The entire stack is defined using AWS CloudFormation or Terraform, making it reproducible and version-controlled. This approach eliminates manual configuration drift and enables easy environment replication.

**Monitoring and Alerts**: CloudWatch logs and metrics provide insights into function performance, error rates, and user behavior. Set up alerts for unusual traffic patterns or errors to maintain high availability.

**Security Best Practices**: IAM roles with least-privilege access, HTTPS enforcement, and regular security updates ensure your portfolio remains secure and professional.

## Performance Optimization 📊

**Caching Strategies**: Implement aggressive caching for static assets while ensuring dynamic content (like visitor count) updates appropriately. Consider browser caching headers and CloudFront cache behaviors.

**Lambda Optimization**: Use connection pooling for database connections, implement proper error handling, and optimize cold start times through provisioned concurrency when needed.

**Asset Optimization**: Compress images, minify CSS/JS, and use modern formats like WebP for better loading performance across all devices.

## Cost Analysis 💰

Breaking down the monthly costs for a cloud portfolio:

- **Route 53 Hosted Zone**: $0.50/month
- **S3 Storage**: $0.02/month (for typical portfolio size)
- **CloudFront**: $0.085/month (first 50GB free)
- **Lambda**: $0.00 (1M free requests/month)
- **RDS (t3.micro)**: $12.60/month OR DynamoDB: $0.25/month

**Total Monthly Cost**: $13-15 with RDS, or $1-2 with DynamoDB

Compare this to traditional hosting solutions that often cost $10-50/month with less scalability and global reach.

## Lessons Learned & Best Practices 🎓

**Start Simple**: Begin with static hosting and add complexity gradually. Don't try to implement everything at once.

**Monitor Everything**: Set up CloudWatch dashboards to track performance, costs, and user behavior. Data-driven decisions lead to better optimization.

**Security First**: Implement HTTPS, use proper IAM roles, and keep dependencies updated. Security should never be an afterthought.

**Document Your Journey**: Keep notes on architectural decisions, challenges faced, and solutions implemented. This documentation becomes valuable interview material.
